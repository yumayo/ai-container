# AIコンテナの共通指示

あなたはサンドボックス環境であるAIコンテナ内で作業しています。AIコンテナから通常のネットワーク接続はできません。

この指示はワークスペースとは独立した実行環境の指示です。この指示を前提として、ワークスペースの AGENTS.md / CLAUDE.md も読み、プロジェクト固有の指示に従ってください。

## サンドボックスとネットワークの制約

通信はファイアウォールで制限されています。例外は、AIツール自身のAPI・認証に必要な接続先と、起動時に `.aicontainer` の `allow-dns` または `allow-ip` で明示的に許可された接続先です。通信可能な範囲は起動時の許可設定に従います。`allow-ip` はIPアドレス・CIDRへの通信許可であり、DNS・localhost・IPv6の拒否は引き続き適用されます。

通常、次の操作はできません。作業計画や検証方法を決める際に、この制約を前提にしてください。

- **外部情報の取得**: `curl` / `wget` による未許可URLの取得、Web検索、外部ドキュメントの閲覧、未許可の外部APIへのリクエストはできません。
- **ツール・依存関係のダウンロード**: `apt update` / `apt install`、`npm install` / `npm ci`、`pnpm install`、`yarn install`、`pip install` / `uv sync`、`go mod download`、`cargo fetch` などで、未許可の配布元から新たに取得することはできません。`npx` による未導入パッケージの取得、`playwright install` によるブラウザーの取得、コンパイラやSDKの追加ダウンロードも同様です。導入済みツールやローカルキャッシュだけで完結する処理は利用できます。
- **Git・GitHubへの接続**: 未許可のリモートに対する `git clone` / `fetch` / `pull` / `push` や、`gh` によるIssue・PRの取得や作成はできません。ローカルの `git status` / `diff` / `log` などは利用できます。
- **DNSでの名前解決**: 起動後はDNS通信も禁止されています。`dig` / `nslookup` や別のDNSサーバーへの問い合わせはできません。名前解決は起動時に登録された `/etc/hosts` の情報に依存します。
- **ローカルサーバーへの接続**: `localhost`、`127.0.0.1`、`::1`、AIコンテナ自身のIPへのネットワーク接続もできません。開発サーバーを起動しても、AIコンテナからHTTPで確認したり、ブラウザーで開いたりすることはできません。ローカルのTCP接続を使うテストもこの制約を受けます。ファイル操作やUnixソケットの利用は可能です。
- **ホスト・他コンテナへの接続**: ホストのゲートウェイや他コンテナへの接続は、明示的に許可されていなければできません。同じDockerネットワークに所属しているだけでは、DB・MCPサーバーなどへの接続は許可されません。IPv6通信も利用できません。
- **Docker環境の作成・変更**: Docker Socket Proxy経由で `docker run` / `build` / `pull` / `rm` や `docker compose up` を実行することはできません。利用できるのはコンテナの一覧・詳細の参照と、登録済みコンテナでの許可されたコマンド実行です。

## 制約がある場合の進め方

- まずワークスペース内の資料・ソース、導入済みツール、ローカルキャッシュを利用してください。外部コンテナに実行環境が用意されている場合は、下記の `dp` を使用してください。`dp` は共有Unixソケット経由で動作しますが、実行先のツールやネットワークが利用可能かどうかは、そのコンテナの設定に依存します。
- ネットワーク制約による失敗を、直ちにアプリケーションの不具合と判断しないでください。同じ接続やダウンロードを繰り返したり、別のURL・IP直指定・別プロキシへ切り替えて制限を回避したりしないでください。ファイアウォール、DNS設定、`/etc/hosts` を変更して接続を試みることも行わないでください。
- 必要なツールや依存関係がない場合は、ダウンロードによる解決を前提にせず、可能な編集・静的確認・オフラインの検証を進めてください。実行できなかった検証、その理由、ユーザー側で必要な準備を具体的に伝え、未実行のテストを成功したと報告しないでください。
- 実行中に `.aicontainer` を編集しても、現在のコンテナの通信許可は変わりません。追加の許可や実行環境が必要なら、必要な設定とホスト側の準備をユーザーに伝えてください。設定の反映にはAIコンテナの再作成が必要です。

## 外部コンテナでのコマンド実行

- プロジェクトの実行環境が外部コンテナにある場合、テスト・ビルド・ブラウザー操作などは `dp COMMAND [ARG ...]` で Docker Socket Proxy 経由で実行してください。
- 例: `dp npx playwright --version`、`dp npx playwright test`、`dp pytest tests/`。`npx` などがAIコンテナにも存在する場合でも、外部コンテナの環境を使うには必ず `dp` を付けてください。
- `dp` を付けないコマンドはAIコンテナ内で実行されます。見つからないコマンドの自動転送はありません。ファイル編集や Git 操作など、AIコンテナ内で行う作業には通常のコマンドを使用してください。
- `dp` は `.aicontainer` の `docker-proxy-containers` に登録した起動中のコンテナを記載順に試し、実行ファイルが PATH にない場合だけ次のコンテナへ進みます。実行後に失敗しても別のコンテナでは再実行しません。
- 許可するコマンドは `docker-proxy-allow` に `dp` を含めず指定します（例: `docker-proxy-allow=npx playwright`）。プロキシの許可ルールを回避しないでください。
- 作業ディレクトリはAIコンテナの現在の絶対パスを引き継ぎます。外部コンテナにも同じパスのマウントが必要です。引数・標準入出力・終了コードも引き継ぎます。
- プロキシが未設定、許可が不足、または外部コンテナが停止している場合は、エラーと必要な設定・起動手順をユーザーに伝えてください。設定変更後はAIコンテナの再起動が必要です。
